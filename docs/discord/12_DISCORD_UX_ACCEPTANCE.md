# Discord UX Acceptance

A dedicated OS bot is not RELEASE-ready until a fresh Discord thread proves:

1. @mention wakes the correct Nano Director.
2. The first operative state is PLANNING.
3. A structured plan is persisted before mutating execution.
4. Exactly one primary progress card is created.
5. Semantic step transitions edit that same card.
6. Raw tools/reasoning do not flood the user channel.
7. A plan revision is visible and auditable.
8. An approval interaction checks user permissions and updates state.
9. A deliberately failed node shows a useful blocked/failure state.
10. A completed run renders a final mission report.
11. `/graph`, `/evidence`, `/status`, `/help` behave correctly.
12. Long choices use selects/modals and are not silently truncated into buttons.
13. The runtime bot does not retain Administrator after provisioning.
