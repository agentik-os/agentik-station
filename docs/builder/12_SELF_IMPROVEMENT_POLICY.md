# Builder Self-Improvement Policy

Hermes already supplies a learning loop. Builder uses it under governance.

## Allowed automatic learning

- compact working preferences
- non-sensitive workflow lessons
- candidate skill improvements
- repeated failure patterns
- better domain heuristics

## Never self-modify without promotion

- locked AGK OS Contract
- Faces hard rules
- client boundaries
- capability/credential permissions
- production approvals
- doctor/release gates
- rollback/recovery requirements
- dedicated Discord bot rule

For Builder and other governance-sensitive profiles, memory/skill writes should be staged for review in stable/production channels. Edge/candidate Nodes may allow more autonomous learning, but promotion into stable is a versioned review event with evidence.
