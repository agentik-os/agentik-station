## Objective and scope

Integrate the user-supplied `stepper-os-v0.1.0 (2).zip` as canonical Station OS
source, delivered by Host and npm installers. Resolve the reported
`master-os-builder` denial without mixing clients, Zones or profile identities.

requested feature-by-feature DevOps audit protocol to native Hermes profiles.

not to unverified version, pricing or configuration claims.

## Constraints and assumptions

- Start from clean main `551b76f` / Station 11.30; publish changed immutable
  release content under a new version, never overwrite an installed release.
- Inspect the ZIP as untrusted data before copying; reject traversal, links,
  special files, duplicate names and unreasonable expansion.
- Canonical editable OS source belongs only under `os/`; generated distributions
  are artifacts. Preserve the supplied domain semantics and record provenance.
- An available package is not an installed/authenticated/operational instance.
  Install software and native profiles where supported; never silently enroll
  credentials, create Discord applications or activate recurring paid work.
- Maximal autonomy applies to authorized, scoped reversible work. Client/Zone
  isolation and approval for destructive/production actions remain intact,
  consistent with the user's explicit DevOps prompt.
- Resolve one owning Zone/instance and its namespaced role map. Do not infer
  user membership from display names or use a role name as a package ID.
- Existing VPS state and accounts must survive; no full bootstrap replay.
