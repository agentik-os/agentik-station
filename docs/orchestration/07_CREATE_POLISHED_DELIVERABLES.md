# Create Polished Deliverables

User-facing artifacts require **taste + render quality gates**, not only file generation.

## Artifact classes

Supported classes include:
- websites/web UI;
- visual assets/posters/social graphics;
- reports/documents;
- slide decks;
- PDFs;
- diagrams/maps;
- data visualizations.

## Gate sequence

```text
brief / audience / purpose
→ content architecture
→ reference/taste direction
→ build
→ render
→ inspect actual render
→ content QA
→ visual QA
→ interaction/accessibility QA where relevant
→ corrections
→ final render/readback
→ delivery evidence
```

## Definition of done

A file existing on disk is **reported produced**, not `verified polished`.

Verification must inspect the appropriate rendered surface: browser view, slide render, PDF pages, image pixels, or other final representation.

## Taste contract

Each artifact mission declares a compact taste brief:
- audience;
- desired impression;
- visual hierarchy;
- density;
- reference qualities;
- avoid list;
- brand constraints;
- quality bar.
