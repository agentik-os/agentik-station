# Orchestration Acceptance Matrix

| Lane | Required proof before strong completion claim |
|---|---|
| Clarify & Plan | objective + constraints + acceptance + plan persisted |
| Build with Leverage | leverage scan recorded for medium/high build work |
| Research & Learn | source packet + freshness/quality metadata + synthesis |
| Code & Ship Safely | configured verification matrix + readback for shipped state |
| Polished Deliverables | final render inspected + content/visual gate |
| Remember & Operate | memory promotion decision + readiness/next repair state |
| Connect Boundaries | connector readiness probe + correct principal/scope |

A mission is `accepted` only when every activated lane satisfies its configured acceptance gate or an explicit owner exception is recorded with reason/evidence.
