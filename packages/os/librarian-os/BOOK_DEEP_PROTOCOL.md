# `/book --deep` Protocol

## Phase 0 — Mission context
Capture: theme, target OS, users, business/domain outcomes, constraints, geography/regulation if relevant, recency sensitivity and known schools of thought.

## Phase 1 — Research map
Create search lanes: foundational theory, applied operator practice, primary evidence, standards/docs, failure literature, competing approaches.

## Phase 2 — Source packet
For every source record store:
- source_id;
- title;
- author/organization;
- year/date when known;
- source_type;
- locator/identifier;
- verification status;
- relevance;
- authority;
- evidence strength;
- independence;
- principles as original synthesis;
- caveats.

## Phase 3 — Distillation
Create a deduplicated matrix of candidate inputs. Inputs are practical design principles, not book summaries.

## Phase 4 — 15 best inputs
Choose 15 non-redundant inputs maximizing mission value, evidence quality and implementation leverage.

## Phase 5 — OS translation
For every input answer:
- What changes in the Nano Director/NanoTeam?
- What skill should exist?
- What should become deterministic?
- What tool or data contract is required?
- What workflow/automation changes?
- What eval detects quality/failure?
- What doctor probe detects breakage?
- What recovery behavior is needed?

## Phase 6 — Builder handoff
Generate `14_BUILDER_HANDOFF.md`, source packet and traceability matrix.
