# Use the installed system deliberately

Read `STATION_RESOURCES.json` in this native profile. It is generated from the
canonical Station resource catalog and exhaustive Host software checklist, not
from a previous user's accounts. Its `DECLARED_NOT_PROBED` state is intentional:
this file makes capabilities discoverable; it does not certify their availability.

1. Resolve this instance/Workstation and the owning Project when working on code.
   Keep OS coordination in its workspace and Project code/dependencies in its
   repository. Never create an unrelated app merely to install all frameworks.
2. Reuse existing code, native Hermes tools and the delivered resources before
   adding a dependency. The preferred stack is Next.js, React, Convex, Clerk,
   Stripe, Tailwind, shadcn/ui, Lucide and Vercel; another justified stack is valid.
   `preferred_stack_plan` is an argv plan, not something to run automatically or
   through a reconstructed shell command. Review existing package/lock files first.
3. Use `station_crawl4ai` for the shipped public-HTML Markdown path and
   `station_scrapegraph` for supported structured extraction with an explicitly
   enrolled provider. Their declaration is not a successful extraction; browser
   dependencies do not mean these adapters execute JavaScript or private sessions.
4. For a Linux Host, ask its authorized operator for `station deps full-check`
   readback when software is missing. Do not elevate yourself or replay bootstrap.
   Workstation uses its own verification report, not a fake Host/Zone context.
   Retain each failed component and its repair action; continue independent work.
5. Honcho/Hindsight are separately selected native memory integrations; Langfuse
   needs its endpoint and scoped tracing account. Server images alone are not
   running services. Never enable every memory backend/MCP at once or copy secrets.
6. ChatbotX, GitHub, Composio, Vercel and Discord need their owning identities and
   real scoped readback. The discord.js SDK is for explicit extensions; Hermes
   remains the only chat gateway. TigerVNC needs a private authenticated display.
   Parakeet's local health is not an accepted voice conversation. Strix belongs
   only on an independently accepted disposable LAB, through the DevOps team.
7. Ponytail's pinned native security rejection is not availability. Do not copy
   the plugin manually, disable scanning or call other software 'Ponytail'. Use
   existing Station engineering guidance and record that capability as unavailable.

Only report **verified** for the exact check actually performed. Record installed
software, account enrollment, successful behavior and live acceptance separately.
